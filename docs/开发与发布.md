# 开发与发布

## 1. 模块职责

代码采用原生 ES 模块，依赖方向从外层适配指向业务层：

```text
web 模板、样式 → adapters/web → application → core
                         └────→ export ────→ core
```

| 目录或模块 | 职责 |
| --- | --- |
| `src/core/dates.js` | 日期序号、范围、星期和学期常量 |
| `src/core/config.js` | 配置输入、规范化、校验与完整性 |
| `src/core/calendar.js` | 逐日计算、周网格、数据导出 |
| `src/core/layout.js` | 月份边界与连续列分组 |
| `src/application/session.js` | 七步动作、配置提交、草稿、导航与撤销 |
| `src/application/holidays.js` | 节日预设、名称对应与下一项 |
| `src/application/school-review.js` | 学校来源和说明的校验与恢复 |
| `src/application/preferences.js` | 视图偏好的格式及配置匹配 |
| `src/adapters/web/main.js` | 事件绑定、会话调用、焦点与保存协调 |
| `src/adapters/web/render.js` | 用会话快照呈现日历和设置卡片 |
| `src/adapters/web/storage.js`、`files.js` | 本地持久化、文件打开和下载 |
| `src/adapters/web/keyboard.js` | 日历键盘入口、方向移动与可见焦点 |
| `src/adapters/web/step-navigation.js` | 七步导航、当前位置与直达操作 |
| `src/adapters/web/motion.js`、`feedback.js` | 步骤过渡、滚动边缘与关联日期提示 |
| `src/export/` | XLSX 工作簿、XML 转义和 ZIP 封装 |
| `src/import/` | 学校工作表、日期网格与说明识别，无平台依赖 |
| `src/sources/` | 学校列表解析和共享目录校验 |
| `src/adapters/node/` | XLSX 读取、网络访问、单轮同步与实时服务 |
| `src/adapters/web/school-source.js`、`school-import.js` | 静态／实时来源适配与导入核对 |
| `data/zju-calendars.json` | 已验证的学校校历及来源信息 |
| `web/calendar.html` | 两套主题共用的界面模板 |
| `web/styles/` | 组件、主题与动画样式 |
| `web/index.html` | 风格选择首页 |

计算层和会话层均可在无界面的 Node.js 环境运行。呈现层读取快照，事件层向会话派发动作，文件导出读取已应用配置。新增平台适配沿用这一依赖关系。

## 2. 运行与构建

使用 Node.js 20 或更高版本。在项目根目录执行：

```sh
node --test
node scripts/build.js
node scripts/serve.js
```

项目使用 Node.js 自带测试与文件工具，无需安装依赖包。`node scripts/serve.js` 先构建，再启动 `http://127.0.0.1:4175`，终端按 Ctrl+C 停止。修改源码后重新运行构建并刷新预览。

构建输出：

```text
dist/
  index.html       风格选择页
  paper.html       暖纸版
  mist.html        清透版
  data/            学校校历目录
  assets/          首页预览图片
  .nojekyll        静态发布标记
```

两套制表页内联同一份脚本和样式，以 `data-theme` 区分外观，均可单独复制并离线打开。首页与 `assets/` 一起保留。输出文件由源码生成，直接修改源码、模板和样式后重新构建。

校历目录随每个主题内嵌，离线时可以直接使用。静态成品另外生成 `data/zju-calendars.json`，页面联网时读取最新版本。`node scripts/sync-calendars.js` 更新源码目录中的数据；本机预览默认提供实时接口，接入配置见 [校历导入](校历导入.md)。

`scripts/bundle.js` 封装项目内部静态 ES 模块，支持命名导入、命名空间导入、声明导出与 `export *`。构建检查循环依赖、项目边界与未处理的模块语法。它只服务本项目的离线产物；引入新的模块语法时同步扩展构建和测试。

## 3. 测试与维护

测试覆盖规则计算、制表会话、视图偏好与键盘、XLSX、学校导入与同步、构建。重点验证日期与业务结果、失败时的状态完整性，以及草稿和已应用配置的边界。

学校导入测试使用官网四个学年的 Excel 原件，验证日期表完整范围、8 + 8 周、月日年份、跨月考试、跨年补课和单次撤销。同步测试覆盖新通知发现、附件更新、失败保留、来源边界和并发请求合并。发布前分别检查两个主题的新建、导入、逐步核对、取消、恢复和撤销。

界面检查覆盖两个主题的完整流程、范围条带、周一起点、逐日考试、连续考试、放假和调课保存、完成预览、继续编辑、文件打开与导出。检查桌面及窄屏下的滚动范围、居中布局、焦点和动画。

规则变更同时维护 [制表规则](制表规则.md)、[交互逻辑](交互逻辑.md)、[数据与接口](数据与接口.md) 和对应测试。注释解释计算边界、数据含义和复杂交互的理由。

## 4. 存储与文件适配

网页配置使用 `academic-calendar-visual-v1` 存储项，视图偏好使用同名加 `-view` 的存储项。存储接口集中在适配层，会话本身只持有内存状态。

离线文件与静态站点的存储空间由运行环境决定。主题在同一来源下共用保存内容。保存配置文件可用于备份和跨设备转移；账户、同步服务和多人协作由宿主产品另行设计。

制表计算、配置保存与导出在本地执行。学校目录可从静态文件读取，也可接入服务端实时同步；同步失败不影响已有配置的编辑与导出。

## 5. 静态站点发布

部署目录为完整的 `dist/`，站点根路径入口为 `index.html`，两个制表页使用相对链接，适合部署到项目子路径。源码、文档、样例和测试组成项目仓库，生成产物单独构建。

项目仓库为 [GuChL9/academic-calendar](https://github.com/GuChL9/academic-calendar)，站点入口为 [风格选择页](https://guchl9.github.io/academic-calendar/)。暖纸、清透分别位于 `paper.html`、`mist.html`。

[发布工作流](../.github/workflows/pages.yml) 在 `main` 分支更新时运行，也可以从 Actions 手动触发，并计划每 6 小时同步学校来源。构建任务使用 Node.js 24，执行测试、同步与构建后上传 `dist/`；部署任务在构建成功后发布到 `github-pages` 环境。构建失败时保留线上已有版本。

仓库的 Settings → Pages 使用 GitHub Actions 作为发布来源。构建任务使用仓库内容写入权限，仅在学校校历内容或来源更新时提交 `data/zju-calendars.json`；同步时间随当次部署更新。部署任务使用 Pages 写入和 OIDC 权限，均使用 GitHub 提供的临时令牌。发布流程参考 [GitHub Pages 自定义工作流说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

计划任务可能因 GitHub 队列延迟；公共仓库长时间无活动时，GitHub 可能停用计划任务，可在 Actions 中恢复。

发布后核对首页图片、两个入口、配置导入、文件导出和刷新恢复。将源码提交并推送到 `main`，即可触发下一次发布。

## 6. 分发

给使用者分发完整的 `dist/` 或单个主题 HTML。给开发者分发完整项目，包含源码、文档、样例和测试。项目内的相对路径使移动目录后仍可构建和运行。
