# 数据与接口

## 1. 配置格式

配置版本为 `schemaVersion: 1`。以下示例可直接交给 `normalizeConfig`：

```json
{
  "schemaVersion": 1,
  "academicYear": 2023,
  "half": "autumn",
  "canvasRange": { "start": "2023-07-01", "end": "2024-02-29" },
  "range": { "start": "2023-07-31", "end": "2024-01-28" },
  "firstMonday": "2023-09-18",
  "firstExams": ["2023-11-11", "2023-11-12", "2023-11-18", "2023-11-19"],
  "secondExams": { "start": "2024-01-09", "end": "2024-01-18" },
  "holidays": [{ "name": "国庆节", "dates": ["2023-10-01", "2023-10-02"] }],
  "adjustments": [{ "kind": "makeup", "date": "2024-01-06", "targetDate": "2024-01-01" }]
}
```

| 字段 | 含义 |
| --- | --- |
| `academicYear` | 学年起始年，整数 |
| `half` | `autumn` 秋冬，`spring` 春夏 |
| `canvasRange` | 空白日历范围 |
| `range` | 制表范围 |
| `firstMonday` | 第一教学周周一，未设置时为 `null` |
| `firstExams` | 秋／春考试日期数组，未设置时为 `[]` |
| `secondExams` | 冬／夏考试连续区间，未设置时为 `null` |
| `holidays` | 放假名称和逐日集合 |
| `adjustments` | `swap` 对调或 `makeup` 补课，两日以 `date`、`targetDate` 表示 |

规范化返回独立对象，输入对象保持原值。日期数组去重排序，名称去除两端空白；所有规则先整体校验。`firstExams`、`holidays`、`adjustments` 输入数组各最多 367 项，每项放假的日期数组最多 367 项。

可接受的输入形式：

- `canvasRange` 省略时采用默认空表，并扩展至覆盖制表范围。
- `holidays`、`adjustments` 省略时使用空数组。
- 放假记录可以使用 `start`、`end` 表示连续输入，规范化展开为 `dates`。
- 放假、调课只保留定义的业务字段，全部通过校验的记录直接生效。
- 不支持的数据版本、无效日期、倒序区间、超限数组和冲突安排抛出错误。

## 2. 计算结果

`generateCalendar(config)` 返回 `{ schemaVersion, config, days, weeks }`。`days` 按日期升序排列，只包含制表范围内日期。

| 逐日字段 | 类型与含义 |
| --- | --- |
| `date` | ISO 日期字符串 |
| `year`、`month`、`day` | 年月日数值 |
| `weekday` | 周一 1 至周日 7 |
| `weekdayLabel` | 星期一等显示文字 |
| `naturalWeekMonday` | 当日所在自然周的周一 |
| `term` | 秋、冬、春、夏或 `null` |
| `teachingWeek` | 1—8 或 `null` |
| `teachingLabel` | 秋八周等名称或 `null` |
| `exams` | 当日考试所属学期数组 |
| `vacation` | 寒假、暑假或 `null` |
| `isWeekend` | 自然周六或周日 |
| `holidays` | 命中记录的 `{ name }` 对象数组 |
| `isHoliday` | 是否存在手工放假记录 |
| `scheduleChanges` | `{ kind, targetDate }` 对象数组，描述当日执行安排 |
| `effectiveScheduleDate` | 采用的原课程日期；无调整时为 `null` |

逐日记录的 `date` 是实际执行日，`effectiveScheduleDate` 指向所采用的原课程日。对调生成两个方向的执行记录；补课只为实际补课日生成记录。原课程日的反向提示由界面查找安排清单得到。

`weeks` 用于表格排版，每项包含自然周周一 `monday`、月份分组 `monthKey`、七个按星期排列的 `cells`、教学周摘要 `label`、学期摘要 `period`。范围外格子为 `null`。

## 3. 公共计算接口

从 `src/core/index.js` 导入：

| 接口 | 返回或用途 |
| --- | --- |
| `blankConfig(year, half)` | 初始空白配置，默认 2026、秋冬 |
| `baseRange(year, half)` | 默认空白日历范围 |
| `normalizeConfig(config)` | 校验并返回规范化配置 |
| `parseConfig(text)` | 解析配置或日历数据 JSON，并校验 |
| `generateCalendar(config)` | 逐日结果与周网格 |
| `exportData(config)` | 可交换的日历数据对象 |
| `status(config)` | `{ complete, missing }` |
| `serial(date)`、`iso(day)` | ISO 日期与 UTC 整日序号互转 |
| `addDays(date, n)` | 日期加减 |
| `weekday(date)`、`mondayOf(date)` | 周一为 0 的星期序号、自然周周一 |
| `datesBetween(start, end)` | 含首尾的日期集合，最多 367 天 |
| `orderedRange(a, b)` | 按时间先后排序的端点 |
| `checkDate(date, label)` | 校验日期及支持年份 |
| `monthBorders(calendar, column, row)` | 日期格四边月份边界 |
| `monthHeaderBorders(calendar, column)` | 周一列对应的表头左右边界 |
| `groupWeeks(weeks, key)` | 连续同值列的 `{ value, start, span }` 分组 |
| `dayMarkers(day)` | 考、休、调、补文字标记 |

日期计算使用 UTC 整日序号，跨时区运行得到相同自然日结果。常量 `TERMS`、`WEEKDAYS`、`NUMERALS` 提供显示名称。

```js
import { blankConfig, normalizeConfig, exportData } from './src/core/index.js';

const config = normalizeConfig({
  ...blankConfig(2023, 'autumn'),
  firstMonday: '2023-09-18',
  firstExams: ['2023-11-11', '2023-11-18'],
  secondExams: { start: '2024-01-09', end: '2024-01-18' }
});
const result = exportData(config);
```

## 4. 制表会话接口

`src/application/session.js` 提供 `createSession(config, view)`。`view` 可传入 `currentStep`、`compact`、`finished`、`schoolSource`。只有第七步可恢复完成预览。

会话提供 `getState()` 与 `dispatch(action)`，二者均返回独立快照。动作在独立副本上完成并校验，失败抛错且保持会话原值。

```js
import { blankConfig } from './src/core/index.js';
import { createSession, previewConfig } from './src/application/session.js';

const session = createSession(blankConfig(2023));
session.dispatch({ type: 'manual-start' });
session.dispatch({ type: 'select-date', date: '2023-07-31' });
session.dispatch({ type: 'select-date', date: '2024-01-28' });
session.dispatch({ type: 'next' });
session.dispatch({ type: 'select-date', date: '2023-09-18' });

const state = session.getState();
const savedConfig = state.config;
const preview = previewConfig(state);
```

主要状态：`config` 为已应用配置；`step` 为 0—6；`finished` 为完成预览；`compact` 为密度；`anchor`、`rangeDraft`、`holiday`、`adjustment` 为草稿；`revision` 在配置变更时增加；`message` 为操作反馈。

| 动作 | 附加字段 |
| --- | --- |
| `year`、`half` | `value` |
| `select-date` | `date` |
| `previous`、`next`、`continue`、`density` | 无 |
| `go-to-step` | `index`：0—6，后退保留假期和调课草稿，前进遵循草稿守卫 |
| `full-range`、`clear-selection`、`clear-second` | 无 |
| `remove-first` | `date` |
| `holiday-preset` | `name` |
| `holiday-name` | `value` |
| `holiday-remove-date` | `date` |
| `holiday-custom`、`holiday-skip`、`holiday-save`、`holiday-cancel` | 无 |
| `holiday-edit`、`holiday-delete` | `index` |
| `adjustment-kind` | `kind`：`swap` 或 `makeup` |
| `adjustment-save`、`adjustment-clear`、`adjustment-cancel` | 无 |
| `adjustment-edit`、`adjustment-delete` | `index` |
| `import` | `config` 对象 |
| `school-import` | `config` 与可选 `source`，提交后从范围开始核对 |
| `new-calendar`、`cancel-new`、`manual-start` | 进入新建、返回原工作、新建空表 |
| `undo`、`escape` | 无 |

界面按照当前步骤派发相应动作。`modeOf(state)` 给出选日方式，`stepNames(config)` 给出步骤名称，`previewConfig(state)` 返回当前预览使用的配置。`stepNavigationIssue(state, index)` 返回跳转受阻原因或 `null`，界面与会话共用此规则。持久化和导出使用 `state.config`。

## 5. 文件

配置 JSON 保存规范化配置。日历数据 JSON 格式为：

```js
{ schemaVersion: 1, kind: 'academic-calendar-data', config, status, days }
```

`parseConfig` 可打开以上两种 JSON。日历数据中的派生结果由配置重新计算。

`src/export/xlsx.js` 的 `createXlsx(config)` 返回 `Uint8Array`，宿主平台负责保存或分享。工作簿包含：

| 工作表 | 内容 |
| --- | --- |
| 校历 | 学期、月份、教学周与日期网格，含月份粗边界 |
| 逐日数据 | 制表范围内的自然日、教学信息、考试、假期、原课程日期等 |
| 放假与调课 | 全部已保存安排，放假逐日展开，调课保留原课程引用 |

日期采用 Excel 日期数值并附带显示格式；1900 年 1—2 月按 Excel 日期系统转换，导出日期与配置一致。单元格文字转义为 XML。导出颜色独立于界面主题。Excel 作为生成结果使用，继续计算时打开配置文件编辑。

## 6. 其他平台接入

计算层和制表会话使用标准 JavaScript，无 DOM、本地文件或网络依赖。其他端可以直接调用模块，将平台输入映射为动作，使用快照绘制界面，并为配置保存、视图偏好和文件输出提供对应适配。

跨端验收应核对相同配置的逐日结果、保存时机、冲突回退、草稿隔离和导出语义。当前交付包含双主题网页适配；小程序和应用软件的界面、宿主存储与文件适配由接入项目提供。

`src/import/zju-workbook.js` 的 `recognizeZjuWorkbook(sheets)` 接收工作表数据并返回 `{ candidates, errors }`。每张表包含 `name`、`date1904`、`cells` 和 `merges`。单元格包含一基 `row`、`column`、`reference`、`value`、`formatId` 和 `format`；合并范围包含 `start`、`end` 行列。候选项包含规范化配置、标题、工作表、核对提示、说明原文和读取依据。

`src/adapters/node/xlsx.js` 的 `readSchoolWorkbook(bytes)` 将 XLSX 转为上述数据。其他平台可提供相同结构复用业务识别。`src/adapters/node/school-sync.js` 提供 `syncSchoolCalendars(options)` 和 `createSchoolCalendarService(options)`，分别用于单轮同步和可复用的实时服务，完整示例见 [校历导入](校历导入.md)。

学校目录格式为：

```js
{
  schemaVersion: 1,
  source: 'https://zhfw.zju.edu.cn/zhfw_xzwj/list1.htm',
  checkedAt: '2026-10-13T00:00:00.000Z',
  status: 'ok', // partial 表示部分来源失败，issues 给出原因
  issues: [],
  calendars: [{
    id, academicYear, title, publishedAt, noticeUrl, attachmentUrl, sha256,
    candidates: [{ title, sheet, config, warnings, notes, evidence }]
  }]
}
```

`normalizeCatalog` 校验目录、官方来源链接和候选配置。页面的静态目录和实时接口使用相同响应格式。选择导入后读取对应学期，成功后派发 `school-import` 并进入统一核对流程；更新失败时由用户选择是否使用保存的结果。保存配置继续采用 `schemaVersion: 1`，最终选定的日期与安排进入配置，来源信息保留在学校目录中，并以 `schoolSource` 随本机视图偏好保存；其字段包含 `academicYear`、`half`、`noticeUrl`、`attachmentUrl`、`publishedAt`、`checkedAt`、`stale`、`warnings` 和 `notes`。来源校验与配置提交原子执行，来源与配置一起撤销。
