# 学校校历导入与同步

## 使用流程

第一步“新建校历”中选择学年和秋冬／春夏学期，然后点击“导入浙大校历”。程序获取对应学期的学校校历并预填配置。用户无需上传文件。

导入后从制表范围开始，依次核对第一教学周、考试、放假和调课。已有值直接显示在日历和设置卡片中；可以沿用、修改或删除，再完成制表。导入与自行制表共用一套步骤。没有修改的核对操作不会增加撤销记录，导入本身可以撤销。

日历下方的“学校说明”默认折叠，包含发布通知、原始 Excel、同步时间、待核对事项和说明原文。说明随当前设备的视图偏好保存，后续编辑仍保留原始来源；新建空白校历时清除，撤销时恢复对应来源。配置 JSON 与日历导出继续保存最终日期及安排。

尚无对应校历时，入口显示可用学年，并保留自行制表选项。同步失败时可以重试或主动选择“使用已保存校历”。修改学年、切换学期或离开新建入口会取消当前请求，晚到的结果不会覆盖当前工作。进入新建入口本身不会替换当前配置，可通过“返回当前校历”继续原来的工作。

## 学校来源与支持范围

来源为浙江大学综合服务网的 [学校行政文件列表](https://zhfw.zju.edu.cn/zhfw_xzwj/list1.htm)，从标题含“浙江大学……学年校历”的正式通知中读取 Excel 附件。同步从列表第一页开始，按分页发现新通知，同时重新核对已有通知与附件，识别附件内容更新。

已核对 2023—2024、2024—2025、2025—2026、2026—2027 四个学年的官方 XLSX，共八个学期。近期附件均采用星期纵排、各周横排、日期表下方列出安排说明的结构。识别使用标题、单元格位置、合并范围和文字含义；日期与教学周需要通过校验。未来沿用同类格式的文件可以自动收录，版式变化或校验失败会显示同步提示并保留已有有效版本。

每份附件最大 5 MiB，ZIP 解压总量最大 30 MiB。读取工作表数值和公式缓存值，不执行公式或外部链接。同一通知有多份 Excel 附件、学年不一致、两个学期不完整或日期表损坏时，该通知本轮不更新。当前自动收录范围从 2023—2024 学年起，教学周采用连续 8 + 8 周。

## 日期与安排规则

| 信息 | 读取依据 |
| --- | --- |
| 学年与学期 | 工作表中的浙大校历标题 |
| 制表范围 | 日期网格内的全部日期，逐格校验连续性与自然星期 |
| 第一教学周 | 教学周行的首个“一”，与秋／春学期开课说明互相校验 |
| 教学周长度 | 连续的“一至八、一至八”，第二学期开课日为第一学期开课后第 56 天 |
| 秋／春考试 | 安排说明中的全部考试日期，允许多行、跨月和不连续区间 |
| 冬／夏考试 | 从全校停课考试开始，到学生寒暑假开始前一天 |
| 寒暑假 | 按第一教学周和末学期考试结束日生成 |
| 放假 | 明确写出“放假”的名称和日期，合并节日保留合并名称 |
| 课程对调 | A 与 B 对调，以及多日“分别与”逐一配对 |
| 补课 | A 补 B 的课，A 为实际补课日，B 为原课程日，支持跨年 |

说明中的月日格式按标题和学期确定年份。Excel 内部日期序列可保留模板年份，显示为“月日”的单元格以其月日和当前学年组成日期；明确显示年份的日期保留该年份并参与校验。

缺少考试说明时提供带缺项提示的可编辑配置。拟定或待定的调课保留文字供核对；明确保存的课程安排直接生效。运动会、报到、毕业、校庆、学生节和小学期等文字保留在说明区，其中明确写出的补课可以导入。小学期日期继续按现有寒暑假规则呈现。

## 两种同步方式

| 部署方式 | 制作时的行为 | 数据更新 |
| --- | --- | --- |
| GitHub Pages | 点击导入或重新同步时，读取站点最新目录 | GitHub Actions 计划每 6 小时抓取学校来源，也可手动运行 |
| 有服务端的部署 | 点击导入或重新同步时，请求同步接口 | 服务端当次抓取学校来源并返回目录，短时间重复请求可合并 |
| 离线 HTML | 使用成品内置的已验证目录 | 联网版本或重新构建时更新 |

GitHub Pages 的静态展示与其他服务器上的实时抓取共用同步模块、Excel 读取、业务识别和目录格式。界面通过来源适配器选择目录文件或实时接口。学校站点未开放跨域读取，实时请求由接入项目的服务端执行。同步环境需要能访问学校来源；学校返回访问限制时，页面显示检查未完成并保留已有目录。

网络失败时，页面展示已保存的数据并说明本次更新失败。同步中单条来源失败时保留其已有版本，其余有效校历仍可更新。同步时间表示本次检查时间，`status: partial` 和 `issues` 表示检查未全部成功。发布通知日期和附件 SHA-256 可用于追溯来源版本。

## 实时接入

Node.js 20+ 可以直接调用：

```js
import { createSchoolCalendarService } from './src/adapters/node/school-sync.js';

const calendars = createSchoolCalendarService({
  initial: savedCatalog,
  save: async catalog => saveCatalog(catalog)
});

// 在宿主服务的 GET /api/school-calendars 中调用并返回 JSON。
const catalog = await calendars.refresh();
```

`initial` 与 `save` 用于接入宿主存储；首次没有历史目录时可省略。并发刷新共用一次抓取，默认一分钟内复用最近结果。`minIntervalMs` 可调整复用时间，`fetchBytes(url, signal)` 可替换网络适配。单次网络请求限时 20 秒，内置实时服务整轮限时 90 秒；服务器可按部署条件调整同步调用方式。

构建实时界面时设置 `CALENDAR_SOURCE_MODE=live`，`CALENDAR_SOURCE_URL` 指向返回目录的接口，默认 `./api/school-calendars`。静态模式为 `snapshot`，默认目录地址为 `./data/zju-calendars.json`。也可调用 `build({ sourceMode: 'live', sourceUrl: '/api/school-calendars' })`。跨域服务需要由宿主配置允许访问的来源。

项目自带 `node scripts/serve.js`，默认同时提供实时接口和双主题页面，可直接验证完整流程。设置 `CALENDAR_SOURCE_MODE=snapshot` 可在本机检查静态部署效果。同步逻辑和工作表识别也可以单独复用，无需使用现有界面。
